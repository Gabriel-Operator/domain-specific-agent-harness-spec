**Binding** connects a portable requirement to a resource available in an installation. A definition can request structured model output, a calendar read, or an approver role. The workspace supplies a compatible model, an authorized calendar account, or the person assigned to review.

## Resolve a portable requirement

### Match capability and scope

| Requirement | Workspace binding | Dispatch check |
| --- | --- | --- |
| A model with structured output | A configured model and provider | The selected model can return the required shape. |
| A connector operation | A provider connection under the requested account context | The actor has a current grant for that operation. |
| A reviewer role | An authorized member or role assignment | The reviewer can decide on this scope and proposal. |
| A logical output | A destination list, artifact, or provider target | The actor can write to that destination under local policy. |

### Example calendar read

This example shows the relationship between a Studio requirement, its workspace binding, and the result. For the persisted requirement format, see [connectors](../connectors/).

```text
portable requirement  calendar:upcoming
workspace binding     authorized calendar for the acting member
runtime mapping       permitted provider operation → meetings result
next step input       meetings
```

## Validate again before dispatch

### Missing or changed bindings

Hold the affected step if an account is disconnected, an operation loses its grant, or the selected model lacks a required capability. Report the missing prerequisite so a workspace owner can repair it.

### Changes after review

Changing an account or destination can change the effect that was reviewed. Compare the dispatch request to the recorded approval and obtain a fresh decision when its scope changes. See the [proposed binding rules](../../specification/#72-binding-) and [approvals](../approvals/).
