A **run** is a concrete attempt to carry out work. It belongs to a workspace and captures the inputs, selected definitions and their revisions, and limits for that attempt. A team goal can delegate to several playbook runs.

## What the workspace records

The runtime records execution state, including status, steps, pending decisions, accepted outputs, and effects. Team and playbook limits bound work such as model calls, elapsed time, and credits. A request to stop a run prevents further work when the runtime can confirm it has stopped. An effect already dispatched may still require reconciliation. It uses the same input identity when handling a repeated start. A blocked step stays blocked when a connection or definition syncs. If the result of a live effect is uncertain, the runtime reconciles it before retrying.

In Meeting desk, a calendar read and a reviewed publication can have different run records. The accepted output can be handed off within the same authorized goal scope.
