A **persona** is the versioned definition of a domain, its teams, and the playbooks they use. A **runtime** imports it and coordinates work. An **agent harness** runs the model and tool loop for an agent. These terms describe responsibilities that an implementation can put in the same process or in separate services.

## Vocabulary

| Term | Meaning in this specification |
| --- | --- |
| [Persona](../concepts/persona/) | The Git definition of a domain model, its teams, and the playbooks those teams can use. |
| [Runtime](../concepts/runtime/) | Software that imports and verifies a persona, connects workspace resources, and coordinates execution. |
| [Agent harness](../concepts/agent-harness/) | The execution system that runs the agent loop, including model calls, context, and tool use. |
| [Agent](../concepts/agents/) | An AI worker configured with instructions and tools. In a Gabriel team definition, the existing field for agent entries is `teams[].bots`. |
| [Team](../concepts/teams/) | Agents and shared resources configured to work together. One persona can declare multiple teams. |
| [Skill](../concepts/skills/) | A reusable bundle of instructions and supporting files that an agent can load. |
| [Goal](../concepts/goals/) | A desired outcome for a team, with criteria for what counts as done. A goal can use existing playbooks or guide the authoring of a new one. |
| [Workflow (playbook)](../concepts/playbooks/) | A prescribed sequence or graph of steps. **Workflow** is the generic term; **playbook** is the name used in Gabriel Studio. |
| [Connector / connection](../concepts/connectors/) | A connector declares which external operations work may call. A connection is an authenticated account that a workspace supplies. |
| [Workspace](../concepts/workspaces/) | One installation's environment, with accounts, permissions, and state. |

For example, Lane is a **persona** for introductions and pilots. Lead researcher and Outreach coordinator are **agents** on one team. The steps for drafting and approving an email are a **playbook**. Sam's connected Gmail account and the resulting email history belong to the **workspace**.

Existing names such as `assets/persona-evals.json`, `teams[].bots`, and published resource keys retain their current meaning. The vocabulary in the docs does not introduce aliases or require a file migration.

The definition of *harness* follows how [OpenAI describes the Codex agent loop](https://openai.com/index/unrolling-the-codex-agent-loop/) and [Anthropic describes agent harnesses](https://www.anthropic.com/research/demystifying-evals-for-ai-agents). The persona runtime owns import and workspace binding in this spec. The draft leaves the harness interface to each implementation.

## Agent Skills

The persona’s root [`SKILL.md`](https://agentskills.io/specification) follows the Agent Skills format. A skills-compatible agent can read those instructions. Additional skills can live under `skills/`. A **skill** gives an agent reusable instructions and supporting files. A **playbook** can use those skills within a workflow whose inputs, outputs, connector operations, and review rules the harness can resolve.

A persona adds a registry and declarative definitions for domains, data, workflows, and evals. A runtime uses those definitions to install the persona and apply its runtime rules. Agent Skills can include executable scripts. The [definitions-only rule](../specification/#3-definitions-only-) applies to the persona’s definition files.

## Model Context Protocol

[Model Context Protocol (MCP)](https://modelcontextprotocol.io/docs/learn/server-concepts) defines how an AI application connects to servers that expose tools and resources. This draft describes which operations a workflow can request and how the runtime binds them to a connection. An MCP tool can satisfy a connector operation once the workspace authorizes the connection.

## Agent2Agent (A2A)

[Agent2Agent (A2A)](https://a2a-protocol.org/latest/specification/) defines how running agents discover one another and exchange tasks and results. An A2A Agent Card describes a service available to call. A persona registry pins files used to load a definition. The draft does not specify an A2A adapter.

## Standard Agent Specification

The [Standard Agent Specification](https://standardagentspec.org/#anatomy-of-the-specification) defines executable agents and their runtime interfaces. A Gabriel persona describes a domain and its teams in Markdown and JSON. Gabriel Studio can distribute playbooks, teams, and personas as npm packages.

| Standard Agent Specification | Related Gabriel concepts |
| --- | --- |
| Providers, models, prompts, and tools | [Model providers](../concepts/model-providers/), [models](../concepts/models/), [prompts](../concepts/prompts/), and [tools](../concepts/tools/) |
| Agents and subagents | [Agents](../concepts/agents/), [teams](../concepts/teams/), and [playbook delegation](../concepts/delegation/) |
| Effects, hooks, and code execution | [Scheduled work](../concepts/scheduled-work/), [lifecycle hooks](../concepts/hooks/), and [code execution](../concepts/code-execution/) |
| Threads, messages, endpoints, filesystem, and execution state | [Context and conversations](../concepts/context-and-conversations/), [files and artifacts](../concepts/files-and-artifacts/), and [runs](../concepts/runs/) |
| Decisions | [Prompted verification](../concepts/prompts/#assemble-the-prompt-for-a-step) can evaluate a candidate against completion criteria during a Studio run. |
| Users (draft) | [Workspace membership](../concepts/workspaces/) and [resource binding](../concepts/resource-binding/) determine which people and agents can act on local resources. |
| Runtime, packaging, and distribution | [Runtime](../concepts/runtime/), [packaging and installation](../concepts/packaging/), and [marketplace](../concepts/marketplace/) |

These are conceptual mappings. Using a Standard Agents package in a Gabriel harness would require an adapter for execution, state, and workspace bindings.
