## Principles

<p class="ps-lead">A persona is a <em>declarative</em> description of a role. Everything that belongs to one installation is supplied when it runs.</p>

<Principles />

## Why a persona format?

<p class="ps-lead">A prompt and a list of tools describe an assistant. They do not describe a role someone can hand real work to, review like any other change, and move between runtimes.</p>

<Story />

## Anatomy of a persona

<p class="ps-lead">At its core, a persona is a folder with a `SKILL.md` file and a set of declarative definition files.</p>

<FileTree>

- persona-archer/
  - SKILL.md Required: name, description and instructions
  - assets/
    - chat-app.json The app people use: pages, actions, data points
    - ontology.json The domain model: entities and relationships
    - persona-evals.json Requirements and the tests that verify them
    - studio-teams.json Optional: teams, their bots, apps and lists
    - data-feeds/ Sources the persona may read
  - references/
    - registry.json Every linked definition, with a fingerprint and revision
    - lists/ Record collections
    - pipelines/ State machines
    - workflows/ Playbooks: the multi-step work the persona carries out
  - skills/ Optional: more Agent Skills the persona brings

</FileTree>

Each part has a section in the specification. The label shows how settled it is.

## Agents, connectors and apps

<p class="ps-lead">A persona can carry the agents that do the work, the connectors they may call and the apps people use to see the result. A runtime keeps all three in step.</p>

<div class="ps-wide"><Loop /></div>

[Apps and connectors](./apps/) specifies each part, the package format for a custom interface, the event stream that keeps every view current, and presence.

## Built on Agent Skills

A persona folder is an [Agent Skill](https://agentskills.io). Its `SKILL.md` follows the Agent Skills format, so any skills-compatible agent can already discover a persona and read its instructions.

This specification adds what a skill does not describe: the definition files, how they are identified and verified, and what a runtime must do with them.

<Layers />

See [Other standards](./standards/) for how the format relates to the Model Context Protocol and the Standard Agent Specification.

## Where do personas run?

- **Gabriel Operator.** The hosted runtime where these personas were first built.
- **[Portable Persona Runtime](https://github.com/Gabriel-Operator/portable-persona-runtime).** A self-hosted appliance that runs a persona's skills, knowledge and workflows on your own hardware.
- **Embedded offline runtime.** Runs the supported subset on a desktop or phone, and reports every step it cannot run offline.

A runtime does not need to support every part of a persona. It must say which parts it supports.
